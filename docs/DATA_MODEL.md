# Second Brain — Data Model & Lifecycle

**Version:** 0.1.0-dev  
**Format Standard:** Obsidian-Compatible Markdown + SQLite

---

## 1. The Four-Stage Data Lifecycle

Knowledge moves through four strictly defined, deterministic stages:

```
┌─────────────────┐      Curator Ingestion      ┌─────────────────┐
│     1. RAW      │ ──────────────────────────► │  2. NORMALIZED  │
│  External Ingest│      - parse & clean        │ Clean Atoms     │
│  - Bildr DB     │      - extract metadata     │ - Uniform text  │
│  - Emails       │      - generate IDs         │ - Verified YAML │
│  - WhatsApp     │                             │ - Provenance ID │
│  - Viber        │                             └────────┬────────┘
│  - Transcripts  │                                      │
└─────────────────┘                                      │ Curator Deduplication
                                                         │ & Classification
                                                         ▼
┌─────────────────┐      Penta GPU / LLM        ┌─────────────────┐
│ 4. SYNTHESIZED  │ ◄────────────────────────── │   3. CURATED    │
│ Deep Insights   │      - entity graph         │ Living Vault    │
│ - Connections   │      - semantic embeddings  │ - Topic notes   │
│ - Summaries     │      - pattern detection    │ - Atomic facts  │
│ - Cross-links   │                             │ - Projects/MOCs │
└─────────────────┘                             └─────────────────┘
```

### Stage 1: RAW
- **Location**: `raw/inbox/` (incoming) → `raw/archive/` (permanent, immutable).
- **Nature**: As-received captures from external sources.
- **Rules**:
  - Source files in `raw/archive/` are **cryptographically preserved and never modified**.
  - Every raw item is assigned a permanent `raw_id`.

### Stage 2: NORMALIZED
- **Location**: Intermediate processing cache (`data/normalized/`).
- **Nature**: Stripped of proprietary formatting, converted to standard Markdown/JSON with consistent ISO 8601 timestamps and canonical source IDs.
- **Rules**: Every record maintains a 1-to-1 link back to its `raw_id`.

### Stage 3: CURATED
- **Location**: `processed/` (The Obsidian Vault) and `moc/`.
- **Nature**: High-value atomic notes structured for both human reading in Obsidian and programmatic querying.
- **Categories & Mutability**:
  | Category | Directory | Mutability | Description |
  |---|---|---|---|
  | `log` | `processed/logs/` | Immutable | Append-only journal & diary entries |
  | `fact` | `processed/topics/` | Immutable | Atomic extracted facts & definitions |
  | `project` | `processed/projects/` | Mutable | Living project documentation |
  | `idea` | `processed/ideas/` | Mutable | Iterative thoughts & essay outlines |
  | `travel` | `processed/travel/` | Mutable | Active travel logs & planning |
  | `moc` | `moc/` | Mutable | Maps of Content (curated index hubs) |

### Stage 4: SYNTHESIZED
- **Location**: `processed/synthesis/` and SQLite vector/FTS indices.
- **Nature**: Machine-generated knowledge artifacts:
  - Vector embeddings for similarity search.
  - Entity-relationship triples (e.g. `[Person A] - (collaborated on) -> [Project B]`).
  - Cross-source executive briefings generated by Qwen 27B on the Penta GPU node.

## 2. Sources vs. Items

To accurately monitor growth and avoid confusion, the system distinguishes between **Sources** and **Items**:

```text
SOURCE DEFINITION               ITEM BREAKDOWN
───────────────────────────────────────────────────────────
1 Bildr SQLite Database   ──►   842 table records
3 Email Accounts          ──►   500 email messages
2 WhatsApp Accounts       ──►   320 conversation threads
1 Viber Account           ──►   570 direct messages
───────────────────────────────────────────────────────────
Total: 7 Sources                Total: 2,232 Raw Items
                                Total: 15,732 Raw Words
```

## 3. SQLite Database Schema (`second_brain.db`)

Operational data, run statistics, token accounting, and provenance are stored in SQLite:

```sql
-- Sources registry
CREATE TABLE IF NOT EXISTS sources (
    source_id TEXT PRIMARY KEY,
    source_type TEXT NOT NULL,       -- 'bildr', 'email', 'whatsapp', 'viber', 'transcript'
    label TEXT NOT NULL,
    account_identifier TEXT,
    created_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP
);

-- Raw items tracking
CREATE TABLE IF NOT EXISTS raw_items (
    raw_id TEXT PRIMARY KEY,
    source_id TEXT NOT NULL,
    file_path TEXT NOT NULL,
    word_count INTEGER DEFAULT 0,
    byte_size INTEGER DEFAULT 0,
    checksum_sha256 TEXT NOT NULL,
    captured_at TIMESTAMP,
    archived_at TIMESTAMP,
    FOREIGN KEY(source_id) REFERENCES sources(source_id)
);

-- Pipeline runs audit log
CREATE TABLE IF NOT EXISTS pipeline_runs (
    run_id TEXT PRIMARY KEY,
    stage TEXT NOT NULL,             -- 'normalize', 'curate', 'index'
    started_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP,
    finished_at TIMESTAMP,
    status TEXT NOT NULL,            -- 'running', 'success', 'failed'
    items_in INTEGER DEFAULT 0,
    items_out INTEGER DEFAULT 0,
    words_in INTEGER DEFAULT 0,
    words_out INTEGER DEFAULT 0,
    error_message TEXT
);

-- LLM inference runs (token & GPU tracking)
CREATE TABLE IF NOT EXISTS llm_runs (
    run_id TEXT PRIMARY KEY,
    job_type TEXT NOT NULL,          -- 'summarize', 'extract_entities', 'chat'
    model TEXT NOT NULL,             -- 'qwen-3.8-27b'
    started_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP,
    finished_at TIMESTAMP,
    duration_ms INTEGER,
    prompt_tokens INTEGER DEFAULT 0,
    completion_tokens INTEGER DEFAULT 0,
    total_tokens INTEGER DEFAULT 0,
    penta_gpu_active BOOLEAN DEFAULT TRUE,
    success BOOLEAN DEFAULT TRUE,
    error_message TEXT
);

-- Hardware & power lifecycle events
CREATE TABLE IF NOT EXISTS power_events (
    event_id INTEGER PRIMARY KEY AUTOINCREMENT,
    timestamp TIMESTAMP DEFAULT CURRENT_TIMESTAMP,
    target_node TEXT NOT NULL,       -- 'penta'
    action TEXT NOT NULL,            -- 'boot_request', 'boot_success', 'shutdown_request', 'power_cut'
    triggered_by TEXT NOT NULL,      -- 'cron_batch', 'manual_ui', 'idle_timeout'
    details TEXT
);
```
